Задание 2. FURPS+ таблица

2.1. Выделите архитектурно-значимые требования. 

Ключевые требования к архитектуре:

1. Безопасность и защита данных
    Шифрование трафика:
        - Обязательно для передачи данных с сайта и интернет-банка (TLS 1.2+).
        - Чувствительные данные (ФИО, телефоны) должны шифроваться при хранении (AES-256).
    Аутентификация и авторизация:
        - Для интернет-банка: двухфакторная аутентификация (логин/пароль + SMS).
        - Для сотрудников бэк-офиса: ролевой доступ (разделение прав кредитного/депозитного отделов).

2. Интеграция систем

    Сайт → Кол-центр:
        - Заявки передаются через REST API с проверкой подлинности (OAuth 2.0).
        - Данные сохраняются в СУБД кол-центра (PostgreSQL).
    Интернет-банк → АБС:
        - Оптимизация: Чтобы не нагружать АБС, использовать асинхронное взаимодействие (очереди сообщений).
        - Технология: RabbitMQ (совместим с .NET и Java), так как Kafka не поддерживается текущей версией интернет-банка.
    СМС-шлюз:
        - Интеграция через API телеком-оператора (HTTPS).

3. Управление процентными ставками 

    Отказ от Excel:
        - Реализовать модуль расчета ставок в АБС на PL/SQL.
        - Доступ для кредитного и депозитного отделов через отдельные интерфейсы.
    Персонализация ставок:
        - Интернет-банк запрашивает ставки для клиента через кэшированные данные из АБС (обновление раз в сутки).

4. Производительность и масштабируемость

    Интернет-банк:
        - Горизонтальное масштабирование: Развернуть на 2+ серверах с балансировкой нагрузки (Nginx).
        - Кэширование: Redis для справочных данных (ставки, условия депозитов).
        - Резервирование: Автоматический переход на резервный ЦОД при сбое.
    АБС:
        - Вертикальное масштабирование (увеличение ресурсов сервера Oracle).
        - Ограничение прямых запросов от интернет-банка — только через очереди.


5. Надежность и отказоустойчивость

    SLA 99.9%:
        - Мониторинг (Prometheus + Grafana) и алертирование при сбоях.
        - Репликация данных между ЦОД.
    Обработка заявок в MVP:
        - Бэк-офис вручную подтверждает заявки в АБС, но клиент получает SMS автоматически.

6. Технологический стек

    Интернет-банк:
        - Язык: C# (.NET Core для совместимости с будущим переходом на микросервисы).
    СУБД: MS SQL (уже используется).
    АБС:
        - Язык: PL/SQL + Delphi (минимальные изменения).
    Кол-центр:
        - Java Spring Boot (оставить текущий стек).

7. Пользовательский опыт (UX)

    Дизайн:
        - Соблюдение корпоративного стиля (цвета, логотипы).
    Скорость отклика:
        - Оптимизация запросов к АБС (кэширование, batch-обработка).
        - Максимальное время ответа — 500 мс.

8. Документация и расширение

    API-документация: Swagger для новых endpoints.
    Архитектурная схема: Описание взаимодействия систем.
